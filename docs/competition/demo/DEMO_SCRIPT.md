# 演示脚本：AI 可解释机器人课堂

## 演示目标

用 10–12 分钟说明一件事：**AI 并非把一段黑盒代码交给学员，而是把任务拆成可查看、可修改、可校验、可回看的 n8n 图与 Blockly 图。**

本案例的主题是“观察、解释与确认”。课堂输入先由 Blockly 处理成可解释的数据，再由另一张 Blockly 图生成机器人计划；n8n 负责设备状态、校验、教师确认、执行编排和结果回看。

## 演示前准备

1. 在本地 n8n 导入 `ai-explainable-robot-classroom.workflow.json`，保持工作流未激活。
2. 打开画布并缩放到能同时看到 `02 准备课堂输入`、两个 Blockly 节点、RoboFrame 节点和教师确认分支。
3. 准备打开两个 Blockly 节点的参数面板，确保能展示“积木”和“生成的 JavaScript 预览”。
4. 若现场连接了 RoboFrame Bridge，在三个 RoboFrame 节点中绑定已保存的凭据；若当天只讲教学链，停在计划、校验和表单确认即可。
5. 实机环节由设备操作员按现场流程完成运动授权。讲解开始前，教师先说明：导入和编辑计划本身不会提交动作。

## 角色与分工

| 角色 | 在演示中的职责 |
| --- | --- |
| 主讲人 | 解释 n8n 图、Blockly 积木和数据/计划之间的映射。 |
| 学员 | 修改一个积木字段或阈值，观察预期输出改变。 |
| 教师 | 审查计划与校验结果，在表单中选择“批准”或“驳回”。 |
| 设备操作员 | 负责现场设备状态和运动授权；不通过 n8n 暴露运动授权开关。 |

## 一、先展示整体图（约 1 分钟）

**画面**：工作流全图。

**讲解词**：

> 这张图不是把 Blockly 放在 n8n 外面当作另一套系统。n8n 是整堂课的主编排：它负责输入、设备状态、校验、教师确认、执行和回看。只有需要表达局部数据逻辑或机器人细节的节点，才在节点内部打开 Blockly。

从左到右指向以下区域：

1. `01 开始课堂演示` 与 `02 准备课堂输入`；
2. `03`、`04` 两个 Blockly Logic 节点；
3. `05`–`08` 的设备状态、计划和校验；
4. `09`–`11` 的教师确认与合并；
5. `12`–`17` 的执行、完成、待检查、驳回和未就绪回看。

## 二、展示确定的课堂输入（约 1 分钟）

**画面**：打开 `02 准备课堂输入`。

**讲解词**：

> 为了让课堂可复现，这个节点准备了一份确定的数据，而不是临时手输。参与度是字符串 `"78"`，三位学员里两位 active，教师确认是必需的，机器人目标是“观察讲台区域、向课堂问候并回到安全位”。

关键输入如下：

```json
{
  "engagementScore": "78",
  "students": [
    { "profile": { "name": "小林" }, "active": true },
    { "profile": { "name": "小陈" }, "active": true },
    { "profile": { "name": "小周" }, "active": false }
  ],
  "teacher": { "name": "张老师", "approvalRequired": true }
}
```

**提问学员**：如果参与度字段来自表单、Excel 或传感器，它为什么有时会是字符串？

## 三、打开第一个 Blockly：把“代码”变成可读积木（约 3 分钟）

**画面**：`03 Blockly · 规范化课堂数据` 的参数面板。

**讲解词**：

> 这里不需要写普通 Code 节点。第一个积木把 `engagementScore` 转成 number，再乘以 1.2，输出 `normalizedEngagement`。第二组积木筛选 `active=true` 的学员，再读取 `profile.name`。右侧 JavaScript 是由积木自动生成的只读预览；真正的执行来源是 Blockly workspace，本身会在运行前重新编译。

逐项指出：

| 积木 | 学员能读到的代码含义 | 本例结果 |
| --- | --- | --- |
| 读取字段 → 转换为数字 → 乘法 | `Number("78") * 1.2` | `normalizedEngagement = 93.6` |
| 数组筛选 | 只保留 `active === true` | 小林、小陈 |
| 字段映射 | 读取每一项的 `profile.name` | `activeStudentNames = ["小林", "小陈"]` |

**互动操作**：把乘法倍率从 `1.2` 改为 `1.1`，让学员先预测输出，再查看生成预览与结果如何同步变化。

## 四、打开第二个 Blockly：把计算结果转成教学解释（约 2 分钟）

**画面**：`04 Blockly · 生成解释卡片` 的参数面板。

**讲解词**：

> 第二个节点读取上一个节点的结果。它用“是否大于等于 80”的条件积木决定课堂分支，再把数值和活跃人数拼成中文解释卡片。这样，学员能同时看到数据计算和面向人的说明如何对应。

预期输出：

```json
{
  "normalizedEngagement": 93.6,
  "activeStudentNames": ["小林", "小陈"],
  "classroomGate": "可进入机器人计划讲解",
  "explanationCard": "输入参与度已规范化为 93.6；已识别 2 名活跃学员。"
}
```

**提问学员**：把阈值从 `80` 改成 `95` 后，哪个积木变了？哪一个 n8n 节点仍然负责整体流程？

## 五、打开 Robot Plan：讲清“计划”和“实机执行”不是一回事（约 2 分钟）

**画面**：`07 Blockly · 生成机器人计划` 的参数面板与编译计划预览。

**讲解词**：

> 这是一张第二类 Blockly 图。它生成的是结构化 `RobotTaskPlan`，不是 JavaScript，也不在这里提交设备动作。计划含有机器人配置标识和 catalog digest，随后由 n8n 把它送去校验、审批和执行。

展示计划步骤：

```text
inspect_scene
  → wait 0.5 秒
  → wave_hello（仅当前一步成功时）
  → recover_safe_pose（仅当前一步成功时）
```

强调三点：

1. `robot = rk3588_training_arm` 与 `configDigest = rk3588-classroom-demo-v2` 是计划的配置标识；
2. 计划里的 guard 只处理“上一步是否成功”的局部条件；设备是否就绪、教师是否批准仍由 n8n 控制；
3. 在此画面修改积木后，得到的是新的计划草稿，尚未进入 RoboFrame 动作提交。

## 六、状态、校验与教师确认（约 2 分钟）

**画面**：依次指向 `05`–`11` 节点。

**讲解词**：

> 这里展示“人机协作”不是一句口号，而是一条不可跳过的工作流路径。RoboFrame 状态节点检查 `motionAuthorized=true` 和 `busy=false`；校验节点核对计划、live catalog digest 和计划摘要；教师表单把“批准”与“驳回”显式写进执行记录。

说明两条分支：

- 设备未就绪：进入 `17 设备未就绪：停在课堂讲解`；
- 教师驳回：进入 `16 已驳回：保留计划，不执行`；
- 条件满足且选择批准：经 `11 合并计划与批准结果` 进入 `12 RoboFrame · 执行计划`。

**教师操作**：在 `09 教师确认（表单）` 先选择“驳回”，展示计划仍可被回看；再说明“批准”对应的唯一执行通路。

## 七、执行回看与收束（约 1 分钟）

**画面**：一次已完成或待检查的 n8n execution。

**讲解词**：

> n8n 的执行记录保存每一步的 taskId、状态和 finalStatus。完成路径进入“执行回看”；失败、取消或未知状态进入“待检查”，方便教师回到对应的 Blockly 积木和计划步骤解释原因。

执行结果应关注这些字段，而不是口头描述设备结果：

```json
{
  "success": true,
  "finalStatus": "completed",
  "taskIds": ["<bridge-task-id>"],
  "steps": [
    { "index": 0, "state": "completed" }
  ]
}
```

**收束词**：

> 这套平台把 AI 生成过程拆成了三层：n8n 解释全局流程，Blockly 解释局部数据和动作计划，RoboFrame 只在状态、校验和教师确认齐备后接收执行请求。学员看到的不再是一段孤立代码，而是一条从输入到执行记录都能追问“为什么”的链路。

## 现场问题速答

| 常见问题 | 回答要点 |
| --- | --- |
| Blockly 是独立平台吗？ | Blockly 嵌入 n8n 节点参数面板；n8n 始终拥有主工作流。 |
| 生成的 JavaScript 能否直接手改？ | 预览用于理解；workspace 是执行真相，运行前会重新编译。 |
| Robot Plan 打开后会动机器人吗？ | Robot Plan 只生成结构化计划。实机路径还要经过状态、校验、教师确认和 Robot Task。 |
| 为什么还要 n8n？ | 它承担触发、跨节点路由、审批、错误分支和执行记录；这些不适合塞进局部积木。 |
| RK3588 出现在哪里？ | `rk3588_training_arm` 和 digest 作为计划配置标识写入编译产物；设备实际可用性以现场 RoboFrame Bridge 的状态和 catalog 为准。 |
